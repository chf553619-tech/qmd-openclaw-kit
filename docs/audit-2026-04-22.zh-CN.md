## Token 节省分析

## 重要边界

这里**不是**在声称一个 provider 账单级的精确节省数字。

这里比较的是两种上下文组织方式：

1. **没有 QMD**：直接重读多个候选文档
2. **有 QMD**：先本地检索，再只精读最相关的文档

这正是当前这套部署的真实目标：
把 QMD 作为**本地检索层**，减少无意义的大段重读。

### 代表性样本文档

以下是当前工作区里几份常见 QMD/OpenClaw 部署文档的估算 token 规模（粗略按 `chars / 4`）：

| 文件 | 估算 tokens |
|---|---:|
| `docs/qmd-setup.md` | 319 |
| `docs/qmd-engine.md` | 323 |
| `docs/qmd-deployment-notes.md` | 330 |
| `memory/2026-04-22-qmd-layer.md` | 278 |
| `projects/qmd-openclaw-kit/README.md` | 1371 |
| `projects/qmd-openclaw-kit/docs/gpu-setup.md` | 582 |
| `openclaw-custom-skills/qmd-retrieval/SKILL.md` | 382 |

**如果把这组文档全量重读一遍，基线约为：`3585` tokens。**

### 检索优先场景估算

假设 query/search 本身带来约 `120` tokens 的轻量开销，然后只读取命中的头部文档。

| 场景 | 估算 tokens | 相对全量重读节省 |
|---|---:|---:|
| 全量重读基线 | 3585 | — |
| 场景 A：query + README + qmd-setup + gpu-setup | 2392 | 33.3% |
| 场景 B：query + README + gpu-setup | 2073 | 42.2% |
| 场景 C：query + qmd-setup + deployment-notes + qmd-layer-memory | 1047 | 70.8% |

### 如何理解这些数字

QMD 的价值不是“让所有问题都变成零成本”，而是：
**先缩小范围，再读真正相关的文档。**

基于当前本地真实文档，这套部署在 QMD / OpenClaw 相关问题上，已经大致具备：

- **约 33%** 的节省：较宽泛、多文档问题
- **约 42%** 的节省：典型部署排障问题
- **约 71%** 的节省：问题很聚焦时

真实节省会随问题类型变化，但这个区间是可信的，因为它是从当前工作区实际文档规模推出来的，不是空口估计。

## 有无 QMD 的差异

### 没有 QMD

智能体更容易出现这种行为：

- 把多个候选 markdown 整篇读进上下文
- README / setup / memory 一起塞进来“以防万一”
- 为了找答案的位置，先消耗大量上下文

在 OpenClaw 这种会不断积累 docs、memory、kit、上游说明的环境里，这种方式很浪费。

### 有 QMD

实际工作流会变成：

- 先做本地快速检索
- 再锁定高概率文档
- 只读相关文档或相关片段
- 只有必要时才升级成大段重读

这就是为什么即使不算 rerank / 高级语义能力，仅凭 retrieval-first 流程本身，效率就已经明显改善。

## 风险与局限

1. **冷启动延迟存在**
   - 语义 / rerank 路径第一次调用时会更慢
2. **还没有自动化 A/B 计费 harness**
   - 当前 token 比较基于文档规模估算，不是 provider 发票对账
3. **collection freshness 仍依赖更新纪律**
   - `qmd collection update-cmd` 提示已经在，但还没有对所有 collection 做统一自动化
4. **QMD 很健康，但 OpenClaw 仍有非 QMD 配置告警**
   - 主要是 `plugins.allow` 这类配置卫生问题

## 建议的下一步

1. 继续把 QMD 作为本地 markdown 知识的默认前置检索层
2. 第一轮优先用非 rerank 的快速检索；rerank 只在必要时启用
3. 逐步为各 collection 自动化 refresh/update 命令
4. 如果后续需要更“硬”的 ROI 证明，就补一个真正的 A/B 观测脚本，记录：
   - query 类型
   - 选中的文档
   - 估算上下文规模
   - provider 实际 prompt tokens（如果能拿到）
